# Orbit PRD 1.0

> Different lives, shared orbit.
> 각자의 궤도를 돌던 사람들이 **취향**이라는 공통점으로 만나는 곳.

- 문서 버전: 1.0 (2026-10-31 확정)
- 기획 출처: ChatGPT 기획 대화 "Orbit 기획 구체화" + 이후 결정 사항
- 관련 문서: [system_design.md](./system_design.md) · [database.md](./database.md) · [api_spec.md](./api_spec.md) · [tasks.md](./tasks.md) · [progress.md](./progress.md)

## 1. 서비스 정의

| 항목 | 내용 |
|------|------|
| 서비스 유형 | 익명 취향 기반 소셜 채팅·커뮤니티 플랫폼 |
| 핵심 사용자 | 자기 취향을 나눌 사람을 찾고 싶지만, 기존 SNS의 공개적인 관계 맺기는 부담스러운 사람 |
| 핵심 가치 | 취향으로 연결되고, 익명으로 대화하며, 자연스럽게 관계를 만든다 |
| 제품 방향 | **채팅 + 커뮤니티 중심** (가상 공간은 홈의 궤도 시각화로만 표현) |
| 초기 목표 | 사용자가 들어와서 취향을 설정하고, 실제로 첫 대화를 시작할 수 있는 서비스 출시 |

### 1-1. 제품 원칙
1. **사람보다 취향을 먼저 발견한다.** 프로필이 아니라 대화하고 싶은 주제로 사람을 만난다.
2. **익명이 기본이다.** 실명·사진·연락처를 요구하거나 노출하지 않는다. 캐릭터와 닉네임으로 표현한다.
3. **관계를 강요하지 않는다.** 팔로워 수, 인기 순위, 친구 수를 만들지 않는다. 들어오고 싶을 때 들어오고 나가고 싶을 때 부담 없이 나간다.
4. **가입 없이도 경험할 수 있다.** 가입은 "기록을 남기고 관계를 이어가고 싶을 때" 하는 선택이다.

### 1-2. 일반 소셜 앱과의 차이
| 일반 소셜 앱 | Orbit |
|---|---|
| 사람을 먼저 발견 | 취향을 먼저 발견 |
| 프로필 중심 | 관심사 중심 |
| 팔로우 중심 | 대화 중심 |
| 실명·사진 중심 | 익명 캐릭터 중심 |
| 관계 형성 후 대화 | 대화하면서 관계 형성 |

## 2. 사용자 유형: Member / Guest

### 2-1. 확정 정책
| 결정 사항 | 확정 내용 |
|---|---|
| Guest 이용 시간 | **30분, 절대 시간제** (최초 입장 시점부터 30분. 활동해도 연장되지 않음) |
| Guest 시간 연장 | MVP에서는 불가 |
| Guest의 대화 범위 | **라운지 + 1:1 취향 매칭 둘 다 허용** |
| Guest → 회원 가입 시 | **진행 중인 대화와 취향을 회원 계정으로 이전** |
| Guest 메시지 저장 | PostgreSQL·분석 로그·오류 로그에 **남기지 않음**. Redis에만 TTL로 임시 보관 |
| Guest 재접속 | 세션 만료 후 다시 오면 **새로운 Guest**로 시작 |

### 2-2. 기능 비교
| 기능 | Member | Guest |
|---|:-:|:-:|
| 서비스 이용 | O | O |
| 닉네임 | 직접 설정 | 랜덤 자동 발급 (예: "익명의 여행자") |
| 캐릭터 | 기본 캐릭터 선택 (V2: 커스터마이징) | 기본 캐릭터 자동 배정 |
| 취향 선택 | DB 저장 | 임시 (Redis) |
| 공개 라운지 | O | O |
| 1:1 익명 채팅 / 매칭 | O | O |
| 오늘의 질문 답변 | O (기록 저장) | O (임시) |
| 채팅 기록 | 저장 | 미저장 |
| 재접속 후 기록 복원 | O | X |
| 세션 시간제한 | 없음 | 30분 |
| 신고·차단 | O | O |

### 2-3. Guest Time Attack (Temporary Orbit)
- 입장 즉시 `guest_id`, 랜덤 닉네임, 기본 캐릭터, `expires_at = 입장 시각 + 30분` 발급
- 화면 상단(또는 홈 카드)에 **실시간 카운트다운** 표시 — 문구 예: "YOUR ORBIT WILL EXPIRE 24:36"
- **만료 시 처리**
  - 모든 채팅방·라운지에서 자동 퇴장, Socket 연결 차단
  - 임시 닉네임·취향·대화 데이터 삭제
  - 앱은 **"궤도가 사라졌어요" 화면**으로 이동 → [회원가입] / [처음으로](Welcome) (#12)
- 서버가 매 요청/소켓 이벤트마다 `expires_at`을 검증한다. **Redis TTL에만 의존하지 않는다.**

### 2-4. 회원가입 유도 (Guest)
- **유도 시점 3가지**
  1. 채팅 기록 저장 버튼을 눌렀을 때
  2. 세션 종료 5분 전
  3. Guest가 일정 횟수(초기값: 메시지 20개) 이상 대화했을 때
- 모달 문구 예: "이 대화를 계속 이어가고 싶나요? 회원가입하면 지금 나눈 대화를 보관하고 다음에도 이어갈 수 있어요." → [무료 회원가입] / [지금은 나중에 할게요]
- 모달을 닫아도 남은 시간 동안은 자유롭게 이용 가능
- 가입 완료 시: 진행 중인 1:1 채팅방·참여 라운지·취향·오늘의 질문 답변을 회원 계정으로 이전 (→ #14)

## 3. 핵심 경험 (MVP)

### 3-1. 취향 시스템
**2단계 구조: 카테고리 → 세부 태그**

| 카테고리 | 세부 태그 예시 |
|---|---|
| 🎵 음악 | Oasis, The 1975, Cigarettes After Sex, Radiohead, Laufey, 혁오, 인디 록, 얼터너티브, 시티팝, 재즈 |
| 🎬 영화 | SF, 로맨스, 스릴러, 애니메이션, 크리스토퍼 놀란, 봉준호 |
| 📚 책 | 소설, 에세이, 인문학, SF 소설, 시 |
| 🍜 음식 | 한식, 일식, 디저트, 카페 투어, 맛집 탐방 |
| ✈️ 여행 | 유럽, 일본, 동남아, 혼자 여행, 캠핑 |
| 🏃 운동 | 러닝, 헬스, 등산, 요가, 클라이밍 |
| 🎮 취미 | 게임, 사진, 전시, 그림, 음악 연주 |

- **중요도**: 매우 좋아함 3점 / 좋아함 2점 / 관심 있음 1점
- 온보딩에서 최소 3개 태그 선택 (권장)
- Member는 DB 저장, Guest는 Redis 임시 저장

### 3-2. 1:1 취향 매칭
- 알고리즘(MVP): 취향 벡터(태그별 중요도 점수) 간 **가중치 코사인 유사도**
  - `similarity(A,B) = (A·B) / (|A||B|)`
  1. 공통 취향 태그 추출
  2. 카테고리별 가중치 반영
  3. 코사인 유사도 계산
  4. 유사도 높은 순 추천
  5. 차단한/차단당한 사용자, 이미 대화 중인 사용자 제외
- 매칭 화면: 상대 캐릭터 + 닉네임 + **공통 취향 2~3개** 표시
- 흐름: [사람 만나기] → 후보 탐색 → 요청 → **양쪽 수락 시** 채팅방 생성
- 대상: 현재 접속 중인 Member + Guest

### 3-3. 취향 라운지 (Lounge)
- 관심사별 공개 그룹 채팅 공간 (예: "새벽의 음악 취향", "영화 이야기", "카페와 일상")
- 실시간 참여 인원 표시, 누구나 자유롭게 입장·퇴장
- 홈에서 내 취향과 맞는 라운지를 추천
- MVP: 운영자가 미리 만든 라운지(seed). **사용자 생성은 V2**

### 3-4. 채팅
- 1:1 익명 채팅 + 라운지 그룹 채팅, Socket.io 실시간
- 대화방 보관 / 나가기
- 모든 채팅에서 신고·차단 지원
- 대화 시작 도우미: 공통 취향 기반 대화 주제 1~3개 추천 (MVP는 템플릿 기반)

### 3-5. 오늘의 질문 (Today's Question)
- 매일 질문 1개 (홈의 주요 카드, 독립 탭 아님)
- 흐름: 답변 작성 → 다른 사람 답변 구경 → 비슷한 답변자와 1:1 대화 시작
- 질문 예시
  - 음악: 평생 한 아티스트의 음악만 들을 수 있다면?
  - 영화: 가장 오래 기억에 남은 영화는?
  - 책: 누군가에게 꼭 추천하고 싶은 책은?
  - 여행: 혼자 여행을 떠난다면 어디로? / 지금 당장 어디든 떠날 수 있다면?
  - 일상: 요즘 가장 기다려지는 순간은?
  - 취향: 남들은 잘 모르지만 나만 좋아하는 것은?
  - 생각: 10년 전 나에게 한마디를 한다면?

### 3-6. 안전 정책
| 항목 | 정책 |
|---|---|
| 실명 / 이메일 / 연락처 | 다른 사용자에게 공개하지 않음 |
| 프로필 사진 | 사용하지 않음, 캐릭터 사용 |
| 실제 사용자 ID | 서버에서만 관리, 클라이언트에는 채팅방별 익명 표시 정보만 노출 |
| 차단·신고 | 모든 채팅(1:1, 라운지)에서 지원 |
| 비속어 필터 | 메시지 전송 시 서버에서 필터링 |
| 스팸 | 동일 메시지 반복·초당 전송 횟수 Rate Limit |
| Guest 신고 처리 | 신고 시점의 해당 메시지만 신고 테이블에 스냅샷 저장 (안전성 검토용 최소 예외) |

## 5. 사용자 여정

**Member**: Welcome → 회원가입(이메일/비번/닉네임) → 기본 캐릭터 선택 → 취향 선택 → Home → 라운지 참여 또는 1:1 매칭 → 대화 지속

**Guest**: Welcome → [가입 없이 둘러보기] → 랜덤 닉네임·캐릭터 발급 + 30분 시작 → 취향 선택(임시) → Home → 라운지/1:1 대화 → (유도 시점에) 가입 모달 → ① 가입: 데이터 이전 후 Member로 계속 / ② 미가입: 30분 후 만료·삭제
